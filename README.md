# screen-translate

Windows 用の常駐アプリです。画面の好きな範囲を OCR して、外国語の文字を日本語の訳文に置き換えて見せます。Google 翻訳の画像翻訳のように、訳文を元の文字の位置に重ねて表示します。処理はすべて PC の中で完結します。

Built with PLaMo.

## 使い方

| キー | 動作 |
| --- | --- |
| Ctrl+Alt+T | 範囲を選び、1 回だけ翻訳する |
| Ctrl+Alt+R | 範囲を選び、リアルタイムで翻訳し続ける。もう一度押すと止まる |
| Ctrl+Alt+X | 翻訳を止めて訳文を消す |

範囲はドラッグで選びます。ドラッグせずにクリックすると、白枠の付いた窓全体を選びます。Esc か右クリックで取り消せます。

範囲を選ぶ画面でもう一度同じホットキーを押すと、前回と同じ範囲を翻訳します。ページをめくったあとの訳し直しは Ctrl+Alt+T を 2 回押すだけです。

訳文は段落ごとに元の文字の上に重なり、文字サイズ、背景色、文字色、太字は元の文字に合わせます。訳文が長いときは、1 行なら右の空きへ広げ、それでも足りなければ文字を小さくします。アイコン、入力欄の枠、画像などの文字以外の部分はそのまま見えています。数字やコードのように訳が変わらないものは置き換えません。

選んだ範囲はその下の窓に結び付きます。窓を動かすと訳文も一緒に動き、サイズを変えると訳し直し、最小化すると隠れます。1 回翻訳の訳文は、範囲の画面が大きく変わると自動で消えます。

選択中も翻訳中もキーボードのフォーカスを取らないので、アクティブウィンドウは変わりません。クリックやスクロールは訳文を通り抜けて下の窓に届きます。

## 設定

タスクトレイのアイコンをダブルクリックすると、設定を開けます。

- 翻訳モデル: 選択、ダウンロード、削除、読み込み、アンロード
- 実行方法: 自動、GPU のみ、CPU のみ
- GPU メモリ上限: 自動のときに、翻訳エンジンが使う GPU メモリの上限を選ぶ
- CPU スレッド数: 自動のときは PC の性能コアの数を使う。好きな数に減らせる
- ホットキー: 3 つの操作それぞれのキー

既定の「自動」は、GPU メモリに載る分を GPU で、残りを CPU で実行します。空きが十分なら全部 GPU に載り、GPU のない PC では CPU だけで動きます。GPU メモリの空きが少ないときは、軽い 0.8B に変えると速く動きます。

RAM の上限はありません。RAM の使用量はモデルの大きさと GPU に載せる量で決まるので、減らすには軽いモデルを選ぶか、GPU に載せる量を増やします。

## 対応言語

ラテン文字の言語（英語、フランス語、ドイツ語、スペイン語など）と中国語を日本語に訳します。日本語の文字には触りません。OCR モデルが読めないので、韓国語、ロシア語、アラビア語、タイ語は翻訳できません。

## モデル

| モデル | サイズ | 目安 |
| --- | --- | --- |
| PLaMo 3 Translate 0.8B | 0.6GB | 軽量。2B の 2 倍ほど速いが誤訳が増える |
| PLaMo 3 Translate 2B | 1.8GB | 標準 |
| PLaMo 3 Translate 8B | 5.3GB | 高品質 |
| PLaMo 3 Translate 31B | 19.5GB | 最高品質 |

ほかのモデルも使えます。GGUF ファイルを `%LOCALAPPDATA%\screen-translate\models` に置くと、設定の一覧に出ます。ファイル名が `plamo-3-translate` で始まらないモデルには、モデル自身のチャットテンプレートで翻訳を依頼します。

## 測定値

RTX 4070 Ti と Core i7-13700F の PC で、PLaMo 3 Translate 2B を GPU で動かしたときの値です。

| 項目 | 値 |
| --- | --- |
| 1 文の翻訳（範囲を決めてから表示まで） | 0.1〜0.3 秒 |
| リアルタイムの更新（文字が変わってから表示まで） | 約 0.2 秒 |
| 画面が変わってから古い訳文が消えるまで | 約 0.04 秒 |
| 2000×1077 の設定画面、約 40 段落 | 最初の表示まで約 1 秒、全部で約 2 秒 |
| アプリを起動して最初の翻訳 | 約 3 秒 |
| アプリのメモリ（待機中） | 9MB |
| アプリのメモリ（動作中） | 約 90MB |
| 翻訳エンジンのメモリ（読み込み中） | 約 380MB |
| GPU メモリ（読み込み中） | 約 2.1GB |

OCR モデルは 60 秒使わないとメモリから外し、翻訳エンジンは 15 分使わないと止めます。アンロードはエンジンの停止なので、メモリも GPU メモリも全部空きます。

実行方法とエンジンの違いは次のとおりです（10 段落の翻訳、4 本同時）。

| 構成 | 時間 | RAM | GPU メモリ |
| --- | --- | --- | --- |
| 自動（既定、この PC では全部 GPU） | 0.68 秒 | 360MB | 2.15GB |
| 自動、GPU メモリ上限 1.5GB | 3.8 秒 | 1.0GB | 1.5GB |
| 自動、GPU メモリ上限 1GB | 6.4 秒 | 1.5GB | 1.0GB |
| CPU のみ（8 スレッド） | 7.5 秒 | 2.2GB | 0 |
| 参考: llama-server + CUDA | 0.6 秒 | 650MB | 2.35GB |
| 参考: Ollama（CUDA） | 0.66 秒 | 1.5GB | 2.3GB |

CPU に回す層が増えるほど遅くなるので、GPU メモリの上限は足りないときだけ使います。上限を付けると、配分を計算するぶん読み込みも約 3 秒長くなります。

## 仕組み

- 画面の取得は GDI の BitBlt で行います。別スレッドが 0.033 秒ごとに画面を見て、変化があれば OCR に渡します。OCR の最中でも変化に気づくので、古い訳文はすぐに消えます。
- OCR は PP-OCRv6 small を rten で CPU 実行します。モデルは exe に埋め込んであります。スレッド数は PC の性能コアの数に合わせます。検出枠の中のインクを行ごとに調べて、文字だけの範囲、背景色、文字色、太字を求めます。
- 翻訳は llama-server を起動して HTTP で依頼します。約 240 文字ずつ 1 行 1 段落でまとめ、4 本同時に流し、1 行できるごとに表示します。まとめた段落どうしが文脈になり、直前のまとまりの原文も参考として渡します。
- 窓の移動は WinEvent で受け取り、OCR をせずに訳文を動かします。
- 重ね表示は透過色つきの最前面ウィンドウです。

## 制限

- リアルタイムの訳文はスクリーンショットや録画に写りません。OCR が自分の訳を読まないようにするためです。1 回翻訳の訳文は写ります。
- 写真やグラデーションの上の文字は、単色の四角で覆って置き換えます。
- 回転した文字は読めません。
- 長辺が 1,600 ピクセルを超える範囲は縮小してから読むので、小さい文字は読みにくくなります。
- 1 回翻訳の訳文は、画素の 8% 以上が変わると消えます。少しのスクロールでは残ることがあります。画面に追従させるにはリアルタイムを使います。
- 排他フルスクリーンのゲームと、拡大率の違う画面が混ざる環境では試していません。

## ビルド

Rust（MSVC）が必要です。

```bash
cargo build --release
```

翻訳エンジンは `engine\llama-server.exe` を exe の隣から探し、なければ Ollama に同梱のものを使います。配布用の zip は次のコマンドで作ります。llama.cpp の公式ビルド（Vulkan 版）を取得して同梱します。

```bash
powershell -ExecutionPolicy Bypass -File scripts/package.ps1
```

画面に触らずに表示を確かめるには、画像に訳文を描いて保存します。

```bash
RENDER_IN=in.png RENDER_OUT=out.png cargo test render_picture -- --ignored --nocapture
```
